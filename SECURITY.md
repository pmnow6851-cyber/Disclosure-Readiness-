# Security and responsible disclosure

**Public repository — no confidential reporting or evidence intake.**

Never post actual disclosures, testimonies, allegations naming identifiable people, evidence files, images of private individuals, customer records, contact details, medical or location data, credentials, recovery codes, tokens, unpublished IP or confidential communications in GitHub issues, discussions, pull requests, commits or action logs.

Issue forms are PUBLIC technical-feedback templates, not a private contact method. Blank-issue restrictions and automated checks can be bypassed and do not make GitHub a secure submission service. Do not send confidential reports to an unverified email or other unverified channel.

A private security reporting channel is **not confirmed as configured or tested**. Until an owner-controlled private channel, safeguarding process and retention/deletion policy have been verified, accept only generic, non-sensitive technical feedback. If an actual credential or other private data has already been exposed, assess it outside this public repository and revoke/rotate affected credentials promptly.

No public submissions, payment, sign-in, analytics, tracking, external APIs, emails, uploads or deployments are authorised. Every new integration requires explicit owner approval and independent privacy/security review.

This documentation is a boundary statement, not proof that the repository history, GitHub settings, third-party forks or future app are free from confidential material.
